# Ordo.lock

`Ordo.lock` is an auto-generated file that records the exact resolved versions and integrity hashes of all dependencies. It ensures reproducible builds across machines and CI environments.

## Location

- In a standalone project, `Ordo.lock` lives next to `Ordo.toml` at the project root
- In a workspace, `Ordo.lock` lives at the workspace root

## When It's Updated

- `ordo build` — creates or updates the lock file if dependencies changed
- `ordo update` — re-resolves all (or specific) dependencies and rewrites the lock file
- `ordo add` — adds the new dependency and updates the lock file

## Format

```toml
# Auto-generated by Ordo. Do not edit manually.
version = 1

[[package]]
name = "fmt"
version = "11.2.0"
source = "vcpkg"
checksum = "sha256:abcdef1234567890..."

[[package]]
name = "sdl"
version = "3.4.8"
source = "git+https://github.com/libsdl-org/SDL#a1b2c3d4e5f6"
checksum = "sha256:..."
script-hash = "sha256:..."

[[package]]
name = "core"
version = "0.1.0"
source = "path+../core"
```

## Fields

### Top-level

| Field | Type | Description |
|-------|------|-------------|
| `version` | int | Lock file format version (currently `1`) |

### `[[package]]`

Each entry in the `[[package]]` array represents a resolved dependency.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Package name |
| `version` | string | Yes | Resolved version |
| `source` | string | Yes | Source URI with type prefix |
| `checksum` | string | No | `sha256:<hex>` integrity hash |
| `script-hash` | string | No | SHA-256 hash of the Lua build script (git deps with `with` only) |

### Source Prefixes

| Prefix | Example | Description |
|--------|---------|-------------|
| `vcpkg` | `vcpkg` | Installed via vcpkg |
| `conan` | `conan` | Installed via Conan |
| `pkg-config` | `pkg-config` | Discovered via pkg-config |
| `system` | `system` | System library (`-l` flag) |
| `git+` | `git+https://github.com/user/repo#commit` | Git dependency, pinned to commit hash |
| `path+` | `path+../core` | Local path dependency |
| `registry+` | `registry+https://registry.ordo.dev` | Ordo registry (future) |

## CI Usage

Use `--locked` or `--frozen` to enforce lock file consistency in CI:

```sh
# Fail if Ordo.lock is out of sync with Ordo.toml
ordo build --locked

# Disallow network access; require all dependencies to be cached
ordo build --frozen
```

## Version Control

`Ordo.lock` should be committed to version control for applications (executables). For libraries, committing the lock file is optional — it ensures reproducible development builds but is not used by consumers.
